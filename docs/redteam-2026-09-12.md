# Jotline red team, 2026-09-12

Baseline: 0.9.1 (`0ba05e3`). Four independent reviewers worked in parallel with
distinct attack surfaces, each required to execute a reproduction before
reporting a finding as confirmed. All probes used synthetic temporary vaults.
A fifth pass read the full source and verified, fixed, and regression-tested
the findings. Repro tests live in `tests/test_redteam_2026_09_12.py`.

| Reviewer | Focus |
| --- | --- |
| Storage | store, history, backups, import, action history, Windows FS shim |
| CLI | subcommands, settings, templates, actions, packaging and release |
| Parsing | regexes, search, links, filters, Drafts import, Markdown preview |
| UI | Textual state machine, modal stack, unsaved-work transitions, CRLF |

The earlier reviews (`redteam-review.md`, `audit/2026-09-10`,
`hardening-2026-09-12`) were provided to each reviewer so effort went to new
or deeper ground. 35 findings were confirmed; 33 were fixed. The rest are
listed under "Not fixed" with the reason.

## High severity (fixed)

- **Notes vanish on filesystems without hard links.** Publishing an existing
  note moved it aside and hard-linked the new file in. On FAT/exFAT, most SMB
  shares and VM shared folders `link(2)` fails with EPERM; the restore path
  also used `link`, so the note stayed under a hidden `.jotline-displaced-*`
  name and the only warning was wiped by the next sidebar refresh. Fix:
  `publish_new` falls back to an existence check plus rename where links are
  refused, the restore path always renames, and warnings that name a retained
  file are sticky.
- **Any daily-backup failure blocked every save, including recovery copies.**
  The first save of a day writes a ZIP of the whole vault before the note's own
  1 KB write; on a nearly full disk this failed on every save all day. Fix:
  the backup failure becomes a warning; the history snapshot taken before an
  overwrite still protects the old text.
- **One invalid settings value wiped all other preferences on the next save.**
  A theme from a newer release or a hand-edit typo made `Settings.load` return
  pure defaults, and the next save (workspace switch, Preferences) rewrote the
  file from those defaults, discarding actions, views, hotkeys and unknown
  keys. Fix: field-by-field fallback that names the bad field; the merge path
  replaces only rejected values; unreadable files are set aside as
  `.jotline-settings.json.invalid-*.json`.
- **Opening a note silently rewrote it.** Textual's document model normalizes
  U+2028/2029, form feed, NEL, lone CR and mixed newlines, so loading such a
  note made the editor text differ from the note, set the dirty flag, and
  autosave rewrote the file within 0.7 s. Imported Drafts text is a common
  source. It also produced false external-change dialogs. Fix: the app keeps
  the editor's own rendering as the baseline and only a change from that
  baseline is an edit.
- **Lone-CR notes crashed the app; CRLF notes gained blank lines.** Task
  toggle, heading/list/quote formatting and find context split the text on
  `\n` while the editor counts `\r` as a line break, so cursor rows indexed
  past the list (IndexError, app exit) or replaced one column too many. Fix:
  use the editor's line model and newline style everywhere.
- **Double dismiss of a modal ended the app.** Enter twice from key repeat,
  Enter then Escape, or a mouse double-click on a palette row delivered two
  dismissals; Textual has no guard, so the second `pop_screen` raised
  `ScreenStackError`, and with nested modals it silently closed the action
  builder without its callback. Fix: a shared `Modal` base that ignores a
  second dismissal.
- **Markdown preview froze the UI for 10 seconds or more on small notes.** The
  256 KiB cap did not bound render cost, which follows block count: 1,000
  headings (4 KiB) took 11 s, 5,000 bullets never rendered. Fix: refuse above
  600 content lines or very wide tables.

## Medium severity (fixed)

- Quadratic regex in Jump to heading (20 KB line: 2.1 s; grows 4x per doubling).
  Replaced with a greedy match and manual closing-hash trim.
- Text search matched one or two characters against random digits of every
  note ID, so the first keystroke of any search listed everything. ID matching
  now needs an 8-character prefix.
- A byte-order mark added by an external editor made the whole metadata header
  part of the body: the note silently moved to inbox/default, lost its star and
  created date, and the next autosave persisted that. The header parser now
  tolerates a leading BOM.
- `jotline run` on a terminal refused the export step after an append step had
  already committed, and every retry appended again; there was no `--raw`.
  Output is now checked before any step runs, and `run` accepts `--raw`.
- `has_terminal_controls` used `str.isprintable`, which rejects CRLF, joined
  emoji, soft hyphens and BOMs. The check now targets C0/C1 controls,
  surrogates and bidirectional overrides only.
- After dismissing the conflict dialog, Ctrl+Q, Ctrl+N and opening a note
  refused silently. Explicit user actions now re-show the dialog.
- First-of-day backup held the vault lock longer than the CLI's one-second
  timeout on large vaults, so a concurrent `jotline capture` failed and dropped
  piped text. Shell commands now wait up to ten seconds.
- Per-save re-validation inflated the whole daily ZIP (0.15 s per save on a
  40 MB vault, 77 s across a 500-note import). Validation is cached per session
  by the archive's inode, size and mtime.

## Low severity (fixed)

- Revision history ordered by local-time string; a clock step backwards offered
  stale content as the latest version and pruned the newest. Ordered by write
  time now.
- Crash mid-write left `.backup-*` and `.jotline-*` temp files forever;
  `doctor` did not report them. Pruned after an hour, reported by `doctor`.
- A corrupt action-history file disabled logging permanently; now set aside.
- Folder import of Jotline's own note files embedded the header as body text;
  their collection, star and dates are carried now.
- Re-selecting the open note in the sidebar wiped its undo history.
- Arrange paragraphs was a no-op on CRLF notes.
- Format heading/list/quote left a stale selection after inserting the prefix.
- Links and `title:` filters could not match a first line longer than 100
  characters (the display title limit).
- Closed stdin produced a traceback; `--vault ""` used the working directory; a
  relative `XDG_DATA_HOME` was honoured against the XDG specification; a closed
  pipe reader (`jotline list | head`) printed an error and exited 1.
- One stray directory or link ending in `.md` in the templates folder hid every
  template.
- Recipe export and file import under a symlinked ancestor (macOS `/tmp`, a
  linked `~/Documents`) failed with "Not a directory"; the error now names the
  link. Recipe export also works without hard links.
- Non-string Drafts `uuid` values leaked Python internals into warnings.
- `add_tags` bypassed the note size guard.
- Read-only commands (`list`, `doctor`, `workspaces`, `tags`, `export`, `actions`)
  created a new empty vault on a mistyped `--vault`; they now fail with
  "Vault does not exist". `path` prints without creating anything.
- Markdown preview now says when raw HTML blocks were not rendered.

## Not fixed

- Status-line word and tag counts run on every keystroke; measured at 100 ms
  only near the 10 MB note limit.
- `preview_import` runs on the UI thread; a 32 MiB import freezes the
  interface briefly but loses nothing.
- Windows: `_windows_fs.py` validates every component of the vault path, so a
  vault beneath an ancestor named like a reserved device is refused. Not
  reproduced (no Windows host).

## Checked and found solid

Header round-trip under 3,000 fuzzed bodies (no metadata injection); every
path-touching call goes through the note-ID pattern; import never overwrites;
temp-file publish order (exclusive create, fsync, link or rename, directory
fsync); corrupt or adversarial history is skipped with warnings; 45 wrong-type
settings payloads all degrade to a diagnostic; template expansion is not
re-entrant and includes are bounded; action steps cannot delete, overwrite or
write outside the vault; capture and append handle invalid UTF-8, binary,
empty and NUL input; the wheel contains only the package; workflow actions are
SHA-pinned with credentials off; all link, tag, template, fence and query
regexes are linear on 100k adversarial inputs; date filters reject every
non-canonical form; the search cache is invalidated by in-app saves; every
editor transition saves or preserves the draft first, and all four branches of
the recovery dialog keep the full draft.
