# Jotline red team, 2026-09-21

Baseline: main at `2606284`, after 0.9.8 and the merges of #28 and #29. Six
independent reviewers worked in parallel on distinct attack surfaces, each
required to execute a reproduction before reporting a finding as confirmed. A
seventh pass re-verified every high-severity finding independently before any
fix was written; two reviewer-supplied file:line references were wrong and were
corrected against the source.

| Reviewer | Focus |
| --- | --- |
| Encryption | crypto, key handling, and every boundary where decrypted text leaves a note |
| Storage | atomicity, locks, the displaced-file protocol, history, backups |
| CLI | arguments, paths, settings, subprocess execution, `$EDITOR`, actions |
| Import/export | untrusted input and output, links, desktop and OS handoff |
| Editor | the Markdown editor and the outliner, with property fuzzing |
| App | search, fuzzy matching, tasks, modal state, algorithmic complexity |

The earlier reviews (`redteam-2026-09-12.md`, `redteam-review.md`,
`hardening-2026-09-12/`) were given to every reviewer so effort went to new
ground. 30 findings were confirmed; the ones below are fixed, and the rest are
listed under "Not fixed" with the reason.

## High severity

- **Searching a note that grows when case-folded spun the UI thread forever.**
  `excerpt` folded the whole body once and then walked it with offsets into the
  body. Case folding is not length-preserving — ß folds to ss, ﬁ to fi, İ to i̇ —
  so the two coordinate systems drift. Where the drift made the skip position
  stop advancing, the loop never terminated: a 97-character German note searched
  for `strasse` pinned the app at 100% CPU until it was killed, losing whatever
  was in the editor. Fix: walk the body's own lines, folding one at a time, with
  a folded-to-raw index map for the two places that mark or slice the original.

- **A note interrupted mid-save vanished from the vault.** An overwrite save
  moves the note aside under `.jotline-displaced-*` and publishes the new text
  under its name; nothing ever reconciled that file. A crash in the one-syscall
  window — reachable constantly, because the TUI autosaves while you type — left
  the only copy under a hidden name, and `jotline list` printed nothing and
  exited 0. The same outcome was deterministic on a filesystem refusing both
  hard links and `RENAME_NOREPLACE` (sshfs, vboxsf, hgfs, some 9p), where the
  restore failed the same way the publish did. Fix: the displaced name carries
  the note ID, because a note file has no ID in its header; a listing puts back
  any displaced original whose name is free; and the restore falls back to a
  plain rename where the flag is refused. The exclusive rename is still tried
  first and still wins against a concurrent creator.

- **A refused structural edit made the outliner overwrite a different block.**
  `change()` ignored whether the write was refused by the size guard, so the
  live tree kept an operation the note never got and `block_rows` addressed a
  tree that did not exist. Retyping one block overwrote another block's text and
  autosaved it. Fix: a refused write re-derives the tree from the note, and
  `sync_block` refuses a row whose lines are not the ones it expects.

- **Four ordinary commands wrote an encrypted note's text out in the clear.**
  Extract selection to new note, Save this note as a template, an action's
  `append` step, and the label on a link to an encrypted note. The external
  editor already refused an encrypted note; these paths were missed. Templates
  are also archived into the daily backup ZIP.

## Medium severity

- **Note text reached the terminal unescaped in the app.** The shell commands
  put every untrusted string through `terminal_text`; the terminal UI escaped
  nothing, and Rich strips BEL, BS, VT, FF and CR but not ESC. A note's title or
  the matched line quoted under a search result could therefore write the user's
  clipboard through OSC 52 — which Jotline itself relies on terminals honouring —
  retitle the window, or forge output. Fix: the policy moved to its own module
  and is applied in the list, the heading, the quoted line and the import dialog.

- **Reading a settings file imported the whole terminal UI.** `Settings.validate`
  imported `outliner_ui` for the outline command names, so `jotline capture` went
  from 0.10s to 0.29s as soon as a settings file existed — undoing most of #29's
  deferred import for every real user. The existing guard only checked import
  time. Fix: the command table is data and lives in a module that imports nothing.

- **A field collision in settings was resolved by the hash seed.** `_partial`
  iterated a set of field names, so which of two colliding fields survived
  differed per process, and the next save wrote the loser back as empty. In three
  runs out of eight the user's whole hotkey map was lost.

- **A malformed Omarchy `colors.toml` stopped Jotline starting.** Deeply nested
  TOML raises `RecursionError`, which the palette loader did not catch, and the
  sync object is built whether or not the theme is in use.

- **Exports were world-readable.** 0644 under the default umask, while notes, the
  key file and history are 0600 — including the export of an encrypted note.

- **`jotline run`'s pre-flight check read truncated text.** A control character
  past 20,000 characters was invisible to it, so the append committed and the
  export was refused afterwards, repeating on every retry. A regression of a
  2026-09-12 fix whose test uses a short body.

- **`jotline sync git` printed an unquoted `cd`.** Wrong out of the box on the
  default macOS vault, and a paste hazard on any path with shell metacharacters.

- **History pruning ranked survivors by the wall-clock stamp in the revision ID.**
  After DST ends or an NTP correction the newest revisions sorted below the old
  ones and were deleted while stale ones were kept.

- **A revision left half-written by a crash held the note in the clear forever.**
  It carries no revision ID, so the purge that runs when a note is encrypted never
  saw it, and no pruning pass covered that folder.

- **Block operations rewrote tabs as spaces.** Indentation was rebuilt as spaces
  on every operation, including ones that reindent nothing, so a Makefile recipe
  line kept in a note stopped working after toggling a task.

- **The outliner's external-change branch re-derived without committing the open
  block**, dropping typed text — the bug class #28 fixed in `settle()`, in the one
  sibling branch that was missed.

## Not fixed

- **Indent and outdent still normalise a tab inside a fenced code block.** There
  the indentation really is being rewritten, and keeping a tab while changing the
  column count needs a decision about what the result should measure. Left for a
  deliberate choice rather than guessed at.
- **`JOTLINE_PASSPHRASE` is inherited by helper processes** (export converters,
  the clipboard helper, `$EDITOR`, the terminal launcher), readable on Linux via
  `/proc/<pid>/environ`. Worth an explicit `env=` on every spawn; not done here
  because it touches five call sites and deserves its own change.
- **A damaged or foreign key file reports "wrong passphrase".** The key file
  carries no identifier, so Jotline cannot tell the two apart, and an
  undecryptable note drops out of `notes()` entirely. Fixing it well means adding
  a non-secret key ID to the file format.
- **Encrypting a note as the first write of the day creates a backup ZIP holding
  its plaintext.** The daily backup runs before the sealed file is published. The
  README already warns that earlier backups keep the old text; the message should
  say today's may too.
- **`change_passphrase` keeps whatever scrypt work factor the key file carries**,
  so a vault written with a weak `n` never gets stronger.
- **A body beginning with a Jotline metadata header is reinterpreted as metadata
  on import**, letting a handed-over note file itself into a collection and hide
  those lines. Low impact, and the fix (require the filename to be a note ID)
  needs thought about hand-edited vaults.
- **Quarantined `.invalid-*.zip` backups accumulate unbounded** and appear in no
  listing.
- **Backup validation inflates a declared manifest into memory** — 200 KB on disk
  cost 200 MiB of RSS — bounded by `MAX_BACKUP_BYTES`.
- **A non-directory at `.jotline-history` makes every save of that note fail.**
  Unlike the daily backup, a history failure is still fatal to the save.
- **Minor CLI polish**: `--encoding` echoes its raw value, `import --apply` exits
  1 on benign preview warnings, and the desktop entry does not escape `%`.
